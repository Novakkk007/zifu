## 一、新知要点（15 条）

### 命理规则层
1. **59 条本命神煞流年适用性裁定初稿**：判定三原则——基准可换柱且目标可投影→A 适用；同构但岁运依据待核→B 条件适用；本命独有（四柱结构/格局语义）→C 不适用（引擎对流年返回 `not-applicable`，区别于「未命中」）。
2. **GPT-6 重分组建议**（消除稿内矛盾）：A 候选 18 / B 待裁定 18 / C 本期排除 23 = 59；数量由证据与批准记录决定，不以凑 21 条为验收目标。
3. **魁罡移出无条件 A**：本命「日柱属性」与流年「干支标签」是对象语义改变而非目标投影；所查《三命通会》文本不足以推出「任何人逢此四种流年干支均命中同一魁罡规则」。空亡、羊刃先列条件项（羊刃：阴阳并录 vs 阳干-only 二选一 + variant/版本/迁移写清；空亡：本命日柱旬×流年支，排除流年自身旬空混用）。金神统一归 C。
4. **换柱通用规则（合同）**：基准不变（本命日干/日支/年支/日柱为基准，非流年自身起例）；目标映射逐条由已批准年度函数决定（全局 `dayPillar→流年干支` 自动授权被删）；命中带 `scope:'liunian'`+`year`；同源=同一规则数据/谓词被不同 scope 适配器复用——**find 与 liunianFind 各复制一张表仍算双份规则**。
5. **D 组=可叠加缺陷清单（非第 4 个互斥组）**：桃花、驿马、华盖、**将星**、劫煞、灾煞 共 6 条「兼顾年支」文案与 find 仅读日支不一致（任务书漏列将星）；亡神不属此类；国印实际基准=年干+日干（非仅日干）。
6. **禄神 ID 不一致（审阅新发现）**：展示层 `shensha.lu.v1` vs 上游 `shensha.lushen.v1`；只在旧数据读取边界做映射，新引擎统一上游 ID，旧别名不得增为第 60 条规则、不得按 name 猜匹配。

### 工程契约层
7. **输出合同四态**：`available`(hit / computed-no-hit)、`not-applicable`、`not-implemented`、`insufficient-input`；空数组无法区分「已算未命中」与「未计算」；reasonCode 分离 `pending-rule-review` / `implementation-pending`；非法输入须类型化校验错误，不得默认甲子/男命。
8. **版本分层**：发布/本命条目/年度规则/输出 schema 四版本分离；旧本命命中元数据冻结（含 19 条 1.5.0 不随年度滚动）；「旧输出全等」=**批准差异清单之外**旧字段全等；新年度金标独立文件（如 `liunian-shensha-web-golden-v1.6.0.json`），不得覆盖旧金标。
9. **打包链 P0 阻断**：小程序引擎/notes 为 esbuild 产物，**禁止手改、禁止继续手贴 notes 尾部**；入口 `.zifu-mp-port-entry.ts`（带点）与构建脚本须找回/重建（含 notes「7+7」导出保留流程）；完成「无规则变更重建演练」前不得动业务算法；本机等效命令须固定工具版本（不可直接粘 POSIX 环境变量）。
10. **端到端接入须显式**：同源代码不会自动建立调用与序列化；独立入口路线≠「Web 无需施工」；未接入则如实缩小交付声明（核心一致性 vs 端到端接入分开验收）。
11. **回落真值表**：回落条件不得用 `items.length`（会把「已计算未命中」误判成「无能力」）；not-applicable/未裁定/insufficient-input 一律不回落补算；仅「旧产物确实无年度能力且处于批准兼容窗口」方可标 display-derived；双轨须写截止版本/触发条件/退出验收，不得成为永久双权威。
12. **状态贯穿三消费点**：buildStepLiunian / buildLiunianNow / buildLnReadCard 均有「丢状态/吞错成空」问题；档位只改可见集合不改求值结果；视图断言应等于批准的 filter/map 投影（空数组永远是子集，子集断言发现不了漏显示）。
13. **判例三轨执行定义**：①规则正确性=独立来源预期值（不得由待测函数或其复制表自动生成；枚举覆盖十干/四组三合/十二支/六旬边界/60 合法日柱）②跨端一致性=同一冻结输入比核心/Web 选定入口/小程序产物 ③人工证据矩阵=按 ruleId×variant×scope（截图 5 个是数量下限）；**人工范围裁定必须在 P1 生效前完成，不能等 P4 才第一次确认魁罡/空亡**。
14. **P0–P4 重排为门禁**：P0 调研与基线冻结（登记两仓库快照/哈希/导出清单、未闭合项标 OPEN）→ P1a 构建恢复（独立工程准备）+ P1b 合同定稿（可并行）→ P2 上游实现（仅已批准子集；不以「模块同源」替代接口验收）→ P3 小程序同步（只走生成链；同一次交付迁移三消费与投影）→ P4 验收（三轨证据+包哈希+回退方案）。
15. **验收边界**：本任务仅年度位置标记，不联动本命评分/取用/吉凶解释；每阶段入口/产物/退出条件须为可核验事实（指向实际文件/命令/输出）；上游完整 vitest 与真机验收未执行前不得宣称通过。

- **本期不写入 `contracts/engines/masters-rules/`，也不动引擎（含 bazi-core）**：流年神煞规则化落点在上游 `contracts/bazi-core/rules/shensha.ts`（非 masters-rules 层）；且任务书经 GPT-6 退回修订、6 项 P0 未闭合、A/B/C 未定稿——无任何规则达到「已批准可实施」门槛，防止「未确认语义被当成已批准算法」。
