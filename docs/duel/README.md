# 紫府 · 问剑体系（对抗式进化 / 打怪升级）

> **玩法**：以「与高手过招」的方式暴露紫府断法的短板 → 每场对战的差距点吸收进内核 → 版本进化。
> **定位**：训练场，不是表演赛。比的是「差距收敛速度」，不是单场输赢。
> **原则**：求败——专挑自己吃不准的案例去打；诚实——断不出就记「未建」，不硬编虚报。

## 一、单场赛制（七步）

1. **立题**：选定一个八字。优先级：① 有现实反馈的真人案例（能验证）→ ② 有明确应期的历史案例 → ③ 纯理论案例（分歧记「待考」）
2. **双盲立断**：紫府先出书面答卷（存 `answers/`，带时间戳密封）；老师独立口头断（不给她看紫府答卷）
3. **亮牌比照**：十维度逐项对照——
   `旺衰 / 格局 / 用神 / 十神心性 / 六亲 / 事业财 / 婚恋 / 健康 / 应期 / 取象`
4. **分歧过招**：分歧点各陈依据、互相质询；紫府有权追问「此断何以得出」——请老师**慢动作回放**推理链
5. **复述确认**：紫府当场复述老师的推演逻辑，请她纠正——确保经验收进来不走样
6. **裁判**：
   - 硬裁判：命主现实反馈
   - 半硬裁判：可查证的应期（年份事件）
   - 无硬裁判 → 记「待考」，不强行判分
7. **结算吸收**：产出《战报》→ 经验卡 → 三类入库（见下）

## 二、经验卡的三个去向

| 去向 | 位置 | 例 |
|---|---|---|
| 规则文档 | `docs/bazi-rules.md` | 「寅月丙火调候取壬」类规则条目 |
| 引擎算法 | `contracts/bazi-core/` | 用神模块从「仅扶抑」扩到「调候/通关/格局」 |
| 解释框架 | AI 参详提示词 | 断语风格、取象表述方式 |

## 三、计分与升级

- **一致率** = 对上维度数 ÷ 可比维度数 → 历史曲线即升级进度条
- **经验卡**：每场目标 ≥3 条可规则化经验（宁少勿滥——每条必须能落成文档条目或代码改动）
- **复战**：隔期重打同一题，验证吸收（上次错的这次改对没有）
- **模块等级**：历法 / 大运 / 神煞 / 旺衰 / 用神 / 格局 / 断事 / 应期 / 取象 / 心性——每战后校准（甲完备 → 丁未建）

工具：`scripts/voice-duel.py`｜桌面快捷：`紫府对战台.command`（双击即用，转写实时显示）
