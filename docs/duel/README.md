# 紫府 · 问剑体系（对抗式进化）

> **定位**：训练方法论与记录（说明层，不定义产品验收标准；与 `docs/specs/` 冲突时以 specs 为准）。
> **玩法**：以「与高手过招」的方式暴露紫府断法的短板 → 每场对战的差距点吸收进内核 → 版本进化。
> **比的是「差距收敛速度」**，不是单场输赢。
> **原则**：求败——专挑吃不准的案例去打；诚实——断不出就记「未建」，不硬编虚报。

## 一、单场赛制（七步）

1. **立题**：选定一个八字。优先级：① 有现实反馈的真人案例（能验证）→ ② 有明确应期的历史案例 → ③ 纯理论案例（分歧记「待考」）
2. **双盲立断**：紫府先出书面答卷（存本目录 `answers/`，带时间戳密封）；对手独立断（不给对方看紫府答卷）
3. **亮牌比照**：十维度逐项对照——
   `旺衰 / 格局 / 用神 / 十神心性 / 六亲 / 事业财 / 婚恋 / 健康 / 应期 / 取象`
4. **分歧过招**：分歧点各陈依据、互相质询；紫府追问「此断何以得出」——请对手**慢动作回放**推理链
5. **复述确认**：紫府当场复述对方的推演逻辑，请其纠正——确保经验收进来不走样
6. **裁判**：
   - 硬裁判：命主现实反馈
   - 半硬裁判：可查证的应期（年份事件）
   - 无硬裁判 → 记「待考」，不强行判分
7. **结算吸收**：产出《战报》→ 经验卡 → 三类入库（见 §二）

## 二、经验卡的三个去向

| 去向 | 位置 | 例 |
|---|---|---|
| 规则文档 | `docs/bazi-rules.md` | 「寅月丙火调候取壬」类规则条目 |
| 引擎算法 | `contracts/engines/`（bazi-core / masters-rules / daily-core） | 取格成破救应深化、调候特例补采 |
| 解释框架 | AI 参详上下文组装（`src/lib/ai-direct.ts` 语料） | 断语风格、取象表述方式 |

**纪律**：每条经验卡必须可溯源（来源=哪场对战哪句）、可落地（文档条目或代码改动），宁少勿滥（每场目标 ≥3 条）。

## 三、计分与升级

- **一致率** = 对上维度数 ÷ 可比维度数 → 历史曲线即升级进度条
- **复战**：隔期重打同一题，验证吸收（上次错的这次改对没有）
- **模块等级**：历法 / 大运 / 神煞 / 旺衰 / 格局 / 用神 / 断事 / 应期 / 取象 / 心性——每战后校准（甲完备 → 丁未建）

## 四、与现有体系的衔接

- **断命体系**（`docs/紫府断命体系.md`）：赛制第 3 步的十维度即七步法「取格 / 定强弱 / 断性格 / 断专题」的对照检查表；对战的「立断」表述遵循断命体系「风格九条」
- **名家参详**（`contracts/engines/masters-rules/`）：SWH / LXR / LJM 输出作为「紫府立断」的表述骨架；对战吸收的经验卡优先回填这两个引擎位
- **产品口径**：全部产出沿用「传统规则结构参考，非客观预测」；红线同产品铁律（不制造恐惧、不承诺结果）

## 五、语音链路（对战工作台 · 参考实现）

工具：`scripts/voice-duel.py`（Mac 环境参考实现；其他平台需替换 ASR/TTS 组件）

| 环节 | 实现 | 状态 |
|---|---|---|
| 听 | funasr 本地转写 + 命理术语纠错词典（乾造/日主/得令类） | ✅ v0.1（~1 秒/段） |
| 想 | 紫府人格对话（盘面注入 + 对打规则，OpenAI 兼容 API） | ✅ v0.1（~5 秒） |
| 说 | macOS say 朗读（可替换 MiniMax/ElevenLabs 等） | ✅ v0.1 |
| 通话接入 | 免提物理桥（即用）/ 虚拟声卡直连（待装） | 🟡 |
| 常驻模式 | 服务化（开机待命、随时开打） | ⬜ 计划 |

```bash
python3 scripts/voice-duel.py --once    # 单回合：说一段 → 转写 → 回应 → 朗读
python3 scripts/voice-duel.py --auto    # 连续对打循环（实战形态）
```
