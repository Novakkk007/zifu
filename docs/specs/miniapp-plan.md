# 紫府小程序方案 v1（2026-08-16 定稿）

> 战略：Web 承载学习/典籍/SEO 获客；微信小程序承载高频交互 + 付费闭环。
> 架构红利：contracts 引擎层纯 TS 与 UI 解耦，可直接复用，仅需重写小程序 UI 层。

## 一、技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | **微信小程序原生**（或 Taro+React） | 微信生态是玄学用户主战场；支付/分享/客服原生能力 |
| 引擎复用 | contracts/ 直接打包（Vite 多入口或独立构建产物） | 九大引擎零改动 |
| 状态 | 小程序 storage API（对应 Web localStorage） | 游客模式一致 |
| 支付 | 微信支付（需个体户执照，挂"工具/数字内容"类目） | 阶段三接入 |

**Taro vs 原生**：Taro（React 语法）可复用 Web 端组件心智，但打包链复杂；
原生小程序更稳但需重学 WXML。建议 **Taro 3.x + React**（与现有技术栈同构）。

## 二、页面结构（MVP）

```
底部 TabBar（3 个）
├── 首页（场景入口四字块 + 每日时令卡）
├── 工具（六爻/奇门/八字/紫微 引擎列表，三才分组）
└── 我的（收藏/历史/偏好/AI key 设置）

页面清单
├── pages/index        首页：四大焦虑入口 + 今日时令速览
├── pages/daily        每日时令（安寝时令在内）
├── pages/tools        工具页（三才分组导航）
├── pages/bazi         八字排盘（表单+结果+名家视角）
├── pages/liuyao       六爻起卦（摇卦动画）
├── pages/qimen        奇门参详
├── pages/hepan        合盘（分享裂变设计：一键转发）
├── pages/profile      我的（本地存储 + 账号即将上线）
└── pages/scenario     场景页（财富/情感/健康，参数区分）
```

## 三、MVP 范围（第一版不做）

- ❌ 紫微/七政/六壬/灵签（Web 有，小程序二期）
- ❌ 支付/会员（阶段三）
- ❌ AI 参详直连（Web 已跑通，小程序需要配置合法域名 api.moonshot.cn——微信后台白名单，可做但放二期）
- ✅ 做：首页/时令/六爻/八字/合盘/我的（引流品 + 两个付费重点 + 基础个人空间）

## 四、合规要点（小程序审核）

1. 类目：选"工具 > 信息查询"或"教育 > 传统文化"（**禁止选占卜类目**）
2. 措辞：全站用词同 Web 版禁词表（参详/参考/趋势）
3. 页脚免责声明必须（每个页面底部）
4. 支付开通前先跑通免费版过审

## 五、开发顺序

1. 项目初始化（Taro 脚手架 + contracts 接入验证）
2. 首页 + 每日时令（引流品先行）
3. 六爻 + 八字（核心引擎）
4. 合盘（分享裂变）
5. 我的（本地存储）
6. 提审上线

## 六、前置依赖

- 微信小程序账号（个人主体可注册，免费）
- 个体户执照（支付阶段才需要）
- 参考小程序（用户提供后吸收版面优点）
