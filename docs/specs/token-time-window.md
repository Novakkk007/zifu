# Token 分时优化方案（避开峰谷，2026-08-20）

> 目标：日间价格高（按量计费模型），把重 Token 任务全部挪进

> 日间只跑轻量任务与订阅免费工人（Codex）。

## 一、时段定价逻辑

| 时段 | 定价 | 适合 |
|---|---|---|
| 00:30-08:30（优惠窗） | DeepSeek ≈5 折 | 重 Token：吸收轮/古籍蒸馏/Kimi 研究/长文分析 |
| 08:30-00:30（常规窗） | 全价 | 轻 Token：验收/部署/巡检/流水线 |
| 任意时段 | Codex（ChatGPT 订阅）边际 0 | 代码重活永远给 Codex |

## 二、架构时间表（重排后）

```
00:30 ┬─ 优惠窗开始 ──────────────────────────────
      │ 03:00 测试快照（基线记录）
      │ 03:30 ★吸收轮（重排：收罗→复核→应用→再复核 + 案例收集）
      │       —— 全部重 Token 大模型调用（DeepSeek/Kimi/OpenClaw 蒸馏）

      │

      │ 08:00 晨检（在窗内收尾：复盘昨晚+派发轻任务）
```

## 三、执行规则

1. **重 Token 任务**（吸收轮/古籍蒸馏/长文研究/神煞典故类）
   → 派发时标注 `时段：深夜`，仅优惠窗执行（03:00-08:00）
2. **轻 Token 任务**（验收/部署/巡检/文案短活）→ 白天随时
3. **Codex**（边际 0）→ 任何时候，代码重活优先它
4. **Kimi/OpenClaw 研究类** → 深夜派（省 Kimi 余额 + OpenClaw 深夜稳定性问题
   已由"任务卡+日志"缓解）
5. 流水线 30min 保持（它只做验收/合并——token 极轻）

## 四、预期节省

- 吸收轮（每天最大 token 消耗，约 3-5 万 tokens 分析）：
  白天 ≈ ¥3-5 → 优惠窗 ≈ ¥1.5-2.5（省 ~50%）
- 晨检/晚检重活同步挪窗
- 日间总消耗预计降低 40-60%
