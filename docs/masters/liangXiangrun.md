# 梁湘润 · 方法论蒸馏

> 定位：本文研究的是公开书目和目录所呈现的判定结构，不认可八字具有经科学验证的预测效力，也不把命例中的事后对应当作因果证据。所有规则只用于文化型、低风险的参详提示。

## 生平与体系概览

行卯出版社的著作年表显示，梁湘润长期整理、编校和撰写子平、星命、神煞、流年等主题书籍；可核对的出版序列包括《余氏用神辞渊》《沈氏用神例解》《细批终身详解》《子平基础概要》《子平母法总则》《子平母法大流年判例》和《金不换大运详解》等。Google Books 的《子平基础概要》书目和目录进一步显示，其入门框架同时讲调候用神、取格、日主强弱、刑冲合会、八格喜忌与大运，不宜把梁氏体系缩写成单一的《子平真诠》格局法。

行卯出版社为《梁湘润八字讲堂》所作的总序，把其工作概括为整理余氏调候、沈氏格局、《滴天髓》强弱和金不换岁运等不同传统。这个概括与现存书目结构能够互相印证，但仍属于利益相关出版社对作者的定位，不能据此证明其方法有效或历史影响程度。较稳妥的说法是：梁氏以文献整理、分类表式和命例演示，把多个子平分支并列到同一教学体系中。

“以大量真人命例研究著称”只能部分核实。《细批终身详解》的公开目录确有大量命例和推演实例，《子平母法大流年判例》的商品介绍也声称案例来自具体人士；但后者是书商转录的作者自述，缺少原始档案、完整样本与独立核验。因此可以确认“著作大量使用命例作为讲解材料”，不能确认案例身份、完整性、命中率或由案例归纳出的规律具有统计效力。

## 核心方法论

### 1. 多轨并审：不让“用神”只有一种含义

**名称：** 调候—格局—强弱分栏评估。

**逻辑链条：**

1. 先排四柱、藏干、十神、生旺库、刑冲合会及大运等基础数据，确保后续各层共享同一份命盘事实。
2. 建立调候层：依据月令季节、日干及全局寒暖燥湿，列出传统调候候选；这里只描述气候平衡方向，不直接判吉凶。
3. 建立格局层：从月令及透藏关系识别格局候选，再分别检查成格、败格、变化、救应与顺用/逆用所需条件。
4. 建立强弱层：检查日主得令、得地、得党以及克泄耗的相对力量，给出强弱区间和置信度，而不是只按五行数量下结论。
5. 三层结论分别保存。只有多层同向且没有明显刑冲合会破坏时，才提高提示权重；相互冲突时，显示冲突来源，不强造唯一“喜用神”。

**适用场景：** 生成结构化参详依据、候选平衡方向和冲突说明；不适合把某个五行永久标成“万能用神”。

**蒸馏结论：** 《子平基础概要》目录把余氏调候、取格、日主强弱和八格喜忌分列，《细批终身详解》也把调候、格局顺逆、日主强弱扶抑列为不同检查项。这说明至少在教学结构上，梁氏不是单轨扶抑法。目录次序可支持工程分层，却不足以证明三者在所有命盘中存在绝对固定的优先级。

- https://www.chinyuan.com.tw/all_book/more?id=9139

### 2. 格局判断：从格名转向成败、变化与救应

**名称：** 格局候选—成败条件—变化复核。

**逻辑链条：**

1. 根据月令及十神透藏提出一个或多个格局候选，不因格名本身预设现实中的好坏。
2. 对每个候选检查其成立条件：关键十神是否出现、是否有根、是否受合冲、制化是否形成。
3. 再查会导致格局失败的反向条件，以及能解除破坏的救应关系。
4. 当合、冲、透干或岁运加入后改变关键关系时，允许格局状态从“候选”变为“成立、受损、转化或不明”。
5. 将顺用/逆用喜忌视为该格局内部的条件表，不把“官、财、印、食为吉，杀、伤、枭、刃为凶”当成无条件标签。

**适用场景：** 解释结构为何成立、为何不成立，以及大运流年加入后结构可能如何变化。

**蒸馏结论：** 《沈氏用神例解》的公开目录明确分出格局成败、变化、常见误用、十四制式与大运喜忌，说明可编码重点应是状态和条件，而不是仅输出一个格名。

本节结论来源：

- https://www.chinyuan.com.tw/all_book/more?id=4903
- https://books.google.com/books?id=Dc4rQwAACAAJ

### 3. 旺衰判断：是独立证据层，不是总开关

**名称：** 得令—得地—得党与克泄耗复核。

**逻辑链条：**

1. 以月令为季节证据，给日主强弱一个初始区间。
2. 检查其余地支的根气、天干地支同类帮助和生扶来源。
3. 同时计算克、泄、耗，以及合冲会局对原有力量的改变。
4. 输出“偏强、偏弱、近中和、从势候选、不明”等区间，并附证据与反证。
5. 旺衰结果只参与扶抑判断；它不能自动覆盖调候需求，也不能取代格局成败判断。

**适用场景：** 生成扶抑候选、识别极端偏态、给格局承载能力提供一项证据。

**蒸馏结论：** 《子平基础概要》将日主强弱细分为得令、得地、得党，同时另列调候用神和八格喜忌；《子平母法总则》目录又把强弱、财官和大量组合分则并置。因此，梁氏与“先定身强弱、再由身强弱唯一决定全部喜忌”的简化扶抑体系并不相同。

本节结论来源：

- https://books.google.com/books?id=Dc4rQwAACAAJ
- https://www.chinyuan.com.tw/all_book/more?id=10032

### 4. 组合与表式：先拆条件，再组合结论

**名称：** 基础事实—局部组合—多证据汇合。

**逻辑链条：**

1. 把十神、禄刃、生旺库、刑冲合会、调候、格局和强弱分别编码为可复查的基础事实。
2. 用条件表描述局部组合，例如“某格局候选 + 某关键十神有效 + 某种合冲未破坏”，而不是保存不可解释的整句断语。
3. 同一主题须至少有两个独立维度同向才提高关注度；只有单一神煞或单一组合时降权。
4. 命例只用于展示条件如何组合，不能反向充当规则真实性或准确率的证明。

**适用场景：** 建立可追踪的规则引擎、向用户解释触发原因。

**蒸馏结论：** 《子平母法总则》公开目录呈现大量分则、总则和实例，《子平秘要》的介绍也强调整理、统计和表式。工程上可以借鉴这种“拆项后组合”的表达方式，但原目录中的疾病、婚姻、伤亡等传统断语必须剥离。

本节结论来源：

### 5. 岁运断法：原局坐标、运年加入、双边复核

**名称：** 原局—大运—流年三层增量计算。

**逻辑链条：**

1. 原局先保留调候、格局、强弱、刑冲合会等多个坐标，不预先压缩成单一吉凶分数。
2. 大运干支加入后，重算十神、强弱、合冲会局及格局成败变化，得到阶段背景。
3. 流年干支再加入，以同样方式识别年度触发或缓解项；流年不得脱离原局和大运单断。
4. 分别比较流年对两个“边”的作用：一边是原局关键结构，另一边是大运形成的阶段结构。二者同向时提高主题权重，方向相反时输出混合提示。
5. 对调候、格局、扶抑三层分别计分。仅当多层同向时提示“关注度上升”；若只是某层触发，明确显示限定条件。
6. 刑冲合会只描述结构关系的变化，不直接映射婚变、疾病、诉讼、死亡等具体事件。

**适用场景：** 生成阶段性和年度性的文化参详主题；不适合预测某年必然发生某件事。

**蒸馏结论：** 《子平母法大流年判例》的目录把调候、格局、冲合、双边喜忌、大运规则、流年与四柱等并列；《细批终身详解》在流年检查项中同列调候、格局顺逆、扶抑和原局刑冲。由此可稳妥蒸馏出“岁运加入后多轨重算”的结构。至于“双边”在每个案例中的精确算法，公开目录不足以完整复原，进入生产前必须用合法正式版本逐条校勘。

### 6. 与常见简化体系的不同点

| 常见简化路线               | 梁氏公开教材所呈现的差异                     | 工程含义                                 |
| -------------------------- | -------------------------------------------- | ---------------------------------------- |
| 只以日主旺衰取一个扶抑用神 | 旺衰之外另列调候、格局顺逆和刑冲合会         | 多轨并算，禁止一个强弱标签覆盖全部结论   |
| 只由月令定格，一格到底     | 继续检查格局成败、变化、救应与大运喜忌       | 格局建模为可变状态，不是静态枚举值       |
| 把调候五行直接当终身吉神   | 调候与格局、扶抑在书目中是不同检查项         | 调候只生成候选方向，并显示与其他层的冲突 |
| 流年单柱直接对应事件       | 目录强调流年与四柱、大运依据、双边喜忌和冲合 | 流年作为增量输入，不允许“一字一事”       |
| 以名人命例证明准确率       | 梁氏著作确有大量命例，但样本与验证链不公开   | 命例只能帮助理解规则，不能作为置信度数据 |

本节为前述书目结构的比较性蒸馏，不代表所有其他命理作者都采用这些简化路线。

### 7. 推荐的引擎执行顺序

```text
输入校验
  → 四柱、藏干、十神、生旺库
  → 刑冲合会基础事实
  → 调候候选面板
  → 格局候选及成败/变化/救应面板
  → 日主强弱及扶抑面板
  → 三面板冲突与同向证据
  → 加入大运并全量复算
  → 加入流年并全量复算
  → 原局/大运双边比较
  → 神煞与单一组合降权
  → 参详主题 + 证据 + 反证 + 置信度
```

这个顺序是面向紫府引擎的保守重构，不宣称是梁氏原书中的唯一固定流程。

## 可应用规则

以下规则只生成参详提示。`有效`表示相关干支未被明显合去或冲制且在统一强度模型中达到最低阈值；所有阈值都必须由版本化配置给出。

1. **LXR-01 三轨同向提示**  
   `调候候选五行有效 + 格局救应候选包含同一五行 + 扶抑候选也包含同一五行 → 提示“调候、格局与强弱三个传统观察维度暂时同向，可提高该平衡方向的参详权重；仍不代表现实事件必然发生”（参考梁湘润体系，来源 https://books.google.com/books?id=Dc4rQwAACAAJ）`

2. **LXR-02 三轨冲突保留**  
   `调候候选与格局喜忌或扶抑候选方向冲突 → 提示“不同传统判定层出现冲突：{调候证据}；{格局证据}；{强弱证据}。暂不合并为唯一用神，请保留多候选并降低置信度”（参考梁湘润体系，来源 https://www.chinyuan.com.tw/all_book/more?id=9322）`

3. **LXR-03 格局成败状态**  
   `月令/透藏形成格局候选 + 成格条件满足 + 败格条件未触发 → 提示“{格局名}具备传统成格条件”；败格条件触发 + 存在有效救应 → 改提示“结构受损但存在{救应关系}，应视为可变状态，不宜仅凭格名定性”`（参考梁湘润《沈氏用神例解》目录，来源 https://www.chinyuan.com.tw/all_book/more?id=4903）

4. **LXR-04 旺衰层限定**  
   `日主得令 + 得地/得党至少一项有效 - 克泄耗未形成明显反转 → 提示“日主在强弱层偏强；该结论只用于扶抑面板，不能覆盖调候或格局结论”；失令但多处得地、得党 → 提示“失令并不等于确定身弱，请降低强弱结论置信度”`（参考梁湘润《子平基础概要》目录，来源 https://books.google.com/books?id=Dc4rQwAACAAJ）

5. **LXR-05 大运结构重算**  
   `加入大运后使原局格局的关键受损项得到制化，或使救应项有效 → 提示“此阶段在传统格局层出现修复信号”；加入大运后破坏原有成格条件 → 提示“此阶段结构条件发生变化，原局格名不可直接沿用”`（参考梁湘润体系，来源 https://www.chinyuan.com.tw/all_book/more?id=4903）

6. **LXR-06 流年双边同向/相反**  
   `流年对原局关键结构与大运阶段结构作用同向 + 至少两个判定面板同向 → 提示“年度信号与阶段背景同向，{主题}关注度上升”；两边方向相反 → 提示“年度与阶段信号相互牵制，呈混合倾向，不宜单年定论”`（参考梁湘润《子平母法大流年判例》目录，来源 https://www.xinyi.hk/goods-2384.html）

7. **LXR-07 刑冲合会去事件化**  
   `岁运触发原局刑冲合会 + 关联到某十神/宫位主题 → 仅提示“{关系/角色/行动}主题的传统结构发生变化，建议结合现实信息观察”；若无格局、调候或强弱层同向证据 → 降为低权重，不生成具体事件`（参考梁湘润体系，来源 https://www.chinyuan.com.tw/all_book/more?id=9322）

8. **LXR-08 命例不增加模型置信度**  
   `规则依据仅为单个命例或事后对应 + 缺少可审计样本与反例 → 提示“此条仅为传统命例说明，不计入模型置信度，也不生成用户级结论”`（研究安全规则，背景来源 https://www.xinyi.hk/goods-2384.html）

上述规则均为紫府依据公开目录所做的工程化重述，不是梁氏原书断语。

## 不可应用部分

1. **生平传奇、宗教身份与“影响深远”宣传：** 出版社总序可作为研究线索，不足以独立证明影响范围，更不能转化为规则权威分。
2. **“真人实事”与命中率主张：** 商品介绍中的案例来源陈述没有隐私授权、原始批文、时间戳、完整样本和反例，不能用于验证准确率。
3. **从命例归纳的疾病、死亡、灾伤、牢狱、婚变等断语：** 不论原书是否列有类似组合，均不得进入产品。
4. **以单一刑冲、神煞、十神或宫位直断事件：** 只能作为低权重文化标签，并须有多层证据与现实限定语。
5. **把调候等同于气象、医学或生理机制：** 寒暖燥湿在这里是传统命理分类，不是临床或自然科学测量。
6. **把格局高低映射为人的尊卑、财富上限或道德价值：** 此类阶层化判断会固化偏见，不进入规则集。
7. **固定“用神”对应颜色、方位、行业、姓名即可改运的承诺：** 公开书目不能支持因果关系，产品不得给出消费或人生决策承诺。
8. **照抄一百六十总则、表格或古今断语：** 现代版本受版权保护，且脱离全书条件容易误用；必须只保留自行重述的抽象判定结构。
9. **由目录反推全部算法细节：** 目录只能证明主题和编排，不能证明精确权重、阈值或绝对优先级；生产实现前必须用合法正式版本校勘。
